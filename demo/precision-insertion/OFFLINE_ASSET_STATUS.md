# Offline asset/use status (2026-10-11)

This page answers **which files the current demo can use for offline
development**. It deliberately does not grade live camera timing, robot
controllers, force control, or physical insertion. `audit_assets()` reports
file presence only; it does not mean a mode has a complete candidate pool.

The reproducible all-mode inventory is generated by
[`audit_offline_asset_profile.py`](audit_offline_asset_profile.py); its local
output is
[`offline_asset_profile_20261011_fullkey1000_reset5000.json`](/home/hyunsu/shared_data/AutoDex/precision_insertion/offline_asset_profile_20261011_fullkey1000_reset5000.json).
It includes the exact staged `reset_12` roots and each directed pose cell,
but does not promote staged seeds into the canonical runtime tree.
Missing mesh-specific FoundPose representations can be generated on the RTX
3090 with [`generate_missing_foundpose.py`](generate_missing_foundpose.py)
and the isolated environment. A generated representation is not yet a
metric-pose accuracy result.

Here **available** means a local file at the expected path; **pending** means
a candidate file exists only in a handoff or lacks independent qualification;
**missing** means no canonical file/pool is present at the expected runtime
path. These labels are about offline inputs, not a claim of robot readiness.

For a minimal file-backed prototype, choose **square 1.5 mm** (all five
tabletop poses now have an eligible endpoint grasp) or **any cylinder gap**
(both poses have an eligible endpoint grasp). All corresponding perception
files are now at canonical local paths, although only their existence and
generator reload have been checked here. A PTH is required only when that
object is actually passed through FoundPose, not for a synthetic known-pose
endpoint screen. The catalog eligibility numbers are offline filters, not
measured grasp or insertion success.

The completed [2026-10-11 NAS handoff](/mnt/paradex2/hyunsu/autodex_precision_insertion_foundpose_generated_20261011)
contains `foundpose_generated_7objects.tar` (5,654,118,400 bytes; read-back
SHA256 `4ce436bec22998fed7c4f91f564f7ef3b1172a2a1999ca15f017b798cdd00094`)
and `manifest.json`. The script writes paths relative to `shared_data`, checks
each archived `repre.pth` against its original SHA256, and emits that manifest.
Extract only into a new/staged `shared_data` tree, then install the seven
object directories without overwriting any recipient's existing canonical
asset. The archive does not contain commissioned pose-accuracy results.
If NAS I/O stops partway through, leave the partial directory untrusted and
retry with a **new** destination rather than merging into it. It does not
measure camera pose accuracy.

An **asset inventory** needs only the matching CAD/object IDs, source files,
and their provenance. A candidate qualified for the proposed offline grasp
pool additionally needs its stock v8 grasp-simulation evidence and the
whole-hand/key 20 mm endpoint screen. Run complete
pickup→lift→transfer→20 mm sampled planning for a *selected hypothetical
scene* when studying that trajectory; this is not a prerequisite for saying
the mesh or candidate file exists. Do not add live timestamp, force,
VLM-confidence or physical-outcome gates to a file-only asset inventory.
Those belong to later execution/evaluation. Conversely, do not call a raw
candidate, a staged reset seed or a
`repre.pth` from another object a usable canonical asset just to make an
inventory appear complete.

The **code** now has a demo-local live action loop and stage handlers for
pickup, lift, transfer, first guarded insertion, one grounded XY retry,
held-key return, transfer-recovery observation and directed repose. The
`run_auto.py` CLI itself still only opens an evidence ledger; the new
[`run_live.py`](run_live.py) CLI drives the live loop through an explicit
AutoDex-PC integration module and independently commissioned controllers.
An optional replayable depth-admission path exists, but no real
held-out depth audit or reviewed calibration is installed. These are runtime
integration/measurement gaps, not missing 3D meshes.
